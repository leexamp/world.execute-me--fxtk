## 一、你在给什么做 MV

**fxtk-pc** —— 一个 C99 单文件 GUI 框架。

| 项 | 值 |
|---|---|
| 语言 | C99，无 C++ |
| 仓库 | `git@github.com:leexamp/fxtk-pc.git` |
| 分支 | `feat/v2.5`（v2.5 全部工作在这里） |
| 提交数 | **216**，时间跨度 **2026-08-07 → 2026-10-10**（约 2 个月） |
| 设计画布 | 480×272（基准分辨率） |
| PC 后端 | **sokol（OpenGL）为默认**；SDL2 降为遗留（仅测试/金图/压测用） |
| 嵌入式 | ESP32 纯 CPU 路径（**接口级编译冒烟通过**，非真机跑通） |
| 依赖 | 零第三方 DLL（Windows 单 exe 达标） |
| 体积 | Linux `fxtk_sim` **385,912 B**（当前）；历史里程碑 144KB / 183KB |

**核心特点**：属性宏写 UI，单文件产物，跨 PC/嵌入式。

```c
fx_widget_t *btn = fx_button(pixel(10,10,100,30), title("确定"), call(on_ok));
```

## 二、⚠️ 能力边界：**真 / 假** 对照表

**这是整份文档最重要的一节。** 原分镜脚本里有 6 处画面在演**不存在的东西**——照拍会让这支 MV 变成虚假宣传，而**这个项目的立身之本恰恰是"没实现的不装实现"**。

### ✅ 真的（可以拍，可以演）

| 能力 | 状态 | 备注 |
|---|---|---|
| 属性宏控件 | ✅ | `pixel/percent/grid/name/title/color/fgcolor/call/value/anim/line/row/page/sidebar/image/radius/border/dense/maxlen/text` |
| 控件池 + 越界保护 | ✅ | `FX_MAX_WIDGETS` |
| 金图回归 / 无头测试 | ✅ | CI 里跑，10 张金图容差 0 |
| 并行 for（**CPU 多线程**） | ✅ | `fx_parallel_for`，POSIX/Win32 线程，**如实叫 par，不叫 gpu** |
| 单指手势 | ✅ | 单击/双击/长按/拖拽/**四向滑动** |
| 弹性布局（子集） | ✅ | `fx_flex_apply`，**不收缩、不换行、最多 64 子件** |
| SVG → canvas（子集） | ✅ | 解析+绘制分离，61 项自检 |
| 单窗口桌面行为 | ✅ | 移动/置顶/居中/拖动 |
| 高 DPI **代码路径** | ⚠️ | 写了，但**实机未验证**（见下） |
| 波形 / 图形 / 3D 光追页 | ✅ | `raymarch` 走 GPU 片元着色器 |
| 压测页 2820 控件 | ✅ | 1080P 软件后端 **13.4ms/帧 ≈ 68–74fps** |

### ❌ 假的（**不要演，或必须改**）

| 原脚本画面 | 现实 | 证据 |
|---|---|---|
| "**多窗口管理**"、`fxtk_windows_manager.c` 构建 | **不存在**。sokol_app 是单窗口设计（全局状态 + 一次 `sapp_run`） | `components/fxtk/fxtk_desktop.h:22` 明写"多窗口必须换平台层" |
| "更多后端（**Wayland**/X11/Windows）" | **Wayland 完全没有**。sokol 在 Linux 只有 X11/GLX | `grep -i wayland third_party/sokol/*.h` → **零命中** |
| "**完整触摸屏多点触控**" | **只有单指**。`touch_read(int*x,int*y,int*pressed)` 只给一个触点 | `components/fxtk/fxtk.h:280` |
| "SVG **复杂路径被完美渲染**" | 是**子集**。圆弧 `A/a`、平滑曲线 `S/s T/t` **明确不支持**，会跳过并计数 | `components/fxtk/fxtk_svg.c:28` |
| "高 DPI **完美适配**，4K 字体锐利" | **代码写了，没在真 HiDPI 屏上验证过**。本机 `sapp_dpi_scale() = 1.000` | CHANGELOG 里自己标了"实机效果未验证" |
| "**去除标题栏**" | 实现了，但 **GNOME/mutter 实测忽略** `_MOTIF_WM_HINTS`，装饰恒 **38px** | 实测记录在 CHANGELOG |
| "压测页接近 **1000fps**" | **不存在**。实测 **68–74fps** | 1080P/2820 控件/SDL 软件后端 |
| "GPU 并行运算" | **不可行**（两个独立阻碍）：<br>① C 代码块无法编译成 GLSL/SPIR-V，除非重写一个 C 子集编译器<br>② sokol_gfx 只有顶点/片元管线，**没有 `sg_dispatch`，没有 `sg_read_image`** | 已实测并写进 CHANGELOG |

### 关于"高 DPI"的准确说法

代码路径已实现（`fxtk_sdl_driver.c` / `fxtk_sokol_driver.c` 各自实现 `fxtk_ui_scale()`，通过 `fx_ui_scale_for()` 统一），
并有 **48,048 组** 穷举自检证明 dpi=1.0 时与旧公式**逐字节一致**。
**但**：本机是普通屏，`sapp_dpi_scale() = 1.000`，所以 **dpi>1 的屏上效果没有实机验证**。

> **MV 里如果要提高 DPI，正确说法是"我写了，但我没见过 2 倍像素的屏"，而不是"完美适配"。**

## 三、项目铁律（**MV 也必须遵守**）

这个项目有一套自我约束，MV 若违反就自相矛盾：

1. **不写"已实现"除非有回读验证。**
2. **环境限制标 `[ENV]` / `[N/A]`，不静默通过。**（例：去标题栏在 mutter 下失败 → 标 `[ENV]`，不写"已修"）
3. **引用测量必须给范围，不给单次读数。** 机器噪声 ±10% 大于真实差异，单次读数会骗人。
4. **体积要在链接后的产物上测，不是 `.o`。**
   —— 这条有血泪史：曾把 `-8,248 B` 误报成 `-46KB`，因为量的是**没加 `-ffunction-sections` 的 `.o`**，把 `--gc-sections` 本来就会丢的代码算进去了。
5. **坑要写进注释**：为什么这么做 + 是什么坑逼出来的。

**把做不到的说成做不到，在这个项目里是加分项，不是丢脸。**

## 四、运行环境（做 MV 时的事实约束）

| 项 | 值 |
|---|---|
| OS | Linux |
| 显示 | **X11**（GNOME Shell/mutter + XWayland），`DISPLAY=:1`，1920×1080 |
| 窗口装饰 | 顶部 **38px**（`_NET_FRAME_EXTENTS` 实测） |
| 编译器 | gcc 13.3.0 |
| 构建 | `cd demo-main && make` → `fxtk_sim` |
| 依赖 | sokol 已 vendor，**不需要装 SDL2** |

**sokol_app 的关键限制**（MV 里可以作为"困住"的隐喻）：
- 单窗口设计
- Linux 仅 X11，**无 Wayland**
- 无 XIM（中文输入）—— 项目**给 X11 打了补丁**接上 XIM（`34e9f29` / `0e68ee2`）
