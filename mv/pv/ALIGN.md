## 0. 结论（先看这个）

| 量 | 值 |
|---|---|
| **片源开头静音长度 S** | **0.11 s**（10 ms 帧口径；0–0.08 s 是数字静音 −240 dBFS，0.10–0.11 s 帧 −63 dBFS，0.11–0.12 s 帧 −35 dBFS） |
| **片源第一个强拍** | **0.25 s**（peak = 1.000，之前 0.11–0.24 s 是一段 −20 dBFS 的弱起） |
| **第一句人声真实起点** | **≈ 0.11 s**（= 片源第一个可听帧。也就是说这条片源**几乎没有前奏留白**，人声在文件最开头就进来了；参考对齐表把这一句标在 0.03 s） |
| **回归 offset（t_lrc → t_真实）** | **+0.10 s**（53 句：mean +0.111 / median +0.110 s；只用检出的 onset 时 37 句 mean +0.053 / median +0.007 s） |
| **残差** | **rms 0.44 s，逐句最大 0.88 s**；分段非线性（见 §3.3），**单靠一个全局偏移修不掉** |
| **波形时长** | 片源最后一个有声帧 207.68 s，之后到 212.331 s 是数字静音 |
| **新 LYOFF** | **4.99 s**（= 5.0 + offset +0.10 − 片源静音 0.11） |
| **冷开场长度 COLDEND** | **5.0 s**（= 音乐第一个音符的落点，不动） |
| **新音轨** | `mv/pv/audio/source_aligned.m4a`，**4.89 s 前导静音 + source.m4a + 尾部补到 217.34 s** |

一句话：**字幕和这条片源之间没有 5 秒级的系统性偏差，全局偏差只有 +0.1 s**。
用户看到的"字幕对不上人声"是**成片把音轨放早了**造成的：
旧的 `source_pad.m4a` 名字叫 pad，但**它没有前导静音**——5 秒静音补在了**文件末尾**
（实测：把它和 source.m4a 对齐，最佳 lag = 0.000 s，前 12 秒逐 100 ms RMS 与 source.m4a 完全一致）。
于是成片里音乐从 t=0.11 s 就响了，而字幕按 `LYOFF=5.0` 在 t=t0+5.0 才出现 →
**字幕整整晚 4.9 秒**。这次把音轨前导 4.89 s（第一个音符正好落在 t=5.0 s 切主界面）之后，
字幕/章节/场景与真实人声就落在同一时刻上了。

## 1. 怎么量的

1. 转单声道 16k：
   ```bash
   ffmpeg -y -i mv/pv/audio/source.m4a -ac 1 -ar 16000 -c:a pcm_s16le /tmp/source16k.wav
   ```
2. 逐 10 ms 帧短时能量（10 ms 帧 = 160 样本，直接算 RMS→dBFS）。
3. 300–3000 Hz 频带能量（25 ms 窗 / 10 ms hop，Hann + rFFT，带内 |X|² 求和）。
4. 谱通量 onset 检测（log1p(50·|X|) 的逐帧正差求和，自适应阈值 = 局部中位数×1.7，
   最小值间隔 60 ms，300–3000 Hz 带内）。全片检出 **531 个 onset（2.5 个/秒）**。
5. **人声起点不能只靠能量/频带**：这条编曲是密集电子，全片 2.5 onset/s，
   任何时刻附近都有 onset，"最近 onset" 这种判据分不出人声和合成器。
   所以额外用了一份**外部对齐参考**做逐句锚点（见 §2），再用我们自己的 onset 交叉验证。

### 3.2 线性回归

- **前 20 句（有 onset 的 20 句）**：`t_真实 = 0.9930·t_timeline + 0.332`，
  **残差 rms 0.339 s，max 0.658 s**。
  （斜率 0.993 ≈ 1 → 没有速度差，只有常数偏移。截距 +0.332 s 被开头几句偏大的偏差抬高了。）

  01_align.py 又没吸到人声那一下）；
- 110–145 s 字幕**偏晚**约 0.2 s；145–175 s 又偏早 0.7 s；
- 所以**残留的是 ±0.4 s 量级的"逐句抖动"**，不是一条直线能修的。

### 3.4 采用的数值

**offset = +0.10 s**（53 句 mean/median 的整取值，±0.15 s 以内）。

这个数**不能单独用**，因为它和"片源自带静音"是两件事：
真实人声在**片源时间轴**上的位置 = `t_timeline + offset`；
而成片把片源整体后移了 `5.0 − S`：

```
字幕出现时刻(成片)      = LYOFF + t_timeline
人声响起时刻(成片)      = (t_timeline + offset) + (5.0 − S)
对齐 =>                   LYOFF = 5.0 + offset − S = 5.0 + 0.10 − 0.11 = 4.99 s
```

即 $LYOFF = 5.0 + (offset − S) = 5.0 + (−0.01) = 4.99$ ——
**这条片源的 0.11 s 自带静音，正好把 +0.10 s 的人声偏移抵消掉了**。
（用户口径的"5.0 + offset"里，offset 就是 offset−S = −0.01 s。）

## 4. 应用（改了哪三个地方）

### 4.1 新音轨 `mv/pv/audio/source_aligned.m4a`

```bash
ffmpeg -hide_banner -loglevel error -y \
  -f lavfi -t 4.89 -i anullsrc=channel_layout=stereo:sample_rate=48000 \
  -i mv/pv/audio/source.m4a \
  -filter_complex "[0:a][1:a]concat=n=2:v=0:a=1,apad=whole_dur=217.34[a]" \
  -map "[a]" -c:a aac -b:a 192k -ar 48000 -ac 2 mv/pv/audio/source_aligned.m4a
```

- 前导静音 = **5.0 − 0.11 = 4.89 s** → 片源第一个音符落在成片 **t = 5.00 s**；
- 总时长 **217.34 s** ≥ 成片 217.33 s（`-shortest` 不会截掉画面）；
- 旧的 `source_pad.m4a` **保留不删**（它没有前导静音，不要再拿去合片）。

### 4.2 `mv/pv/web/mv.html`

- `const COLDEND=5.0;`（冷开场结束 = 音乐起点，不动）
- `const LYOFF=4.99;`（原来 5.0；改的是正片内容轴）
- `window.renderFrame = t<COLDEND ? coldOpen(t) : renderMain(Math.max(0,t-LYOFF))`
  ——两处重复定义都改了。字幕 `lyricAt`、章节 `secAt`、场景 `sceneOf/sceneFrame`
  全部走 `renderMain(t)` 这一个入参，**三者仍然同一时刻**。
  （`sceneOf` 内部另有 `LEAD=0.2 s` 的"提前取句"，是画面自己的观感补偿，本次没动。）
- 预览控制栏 `au.src` 改成 `../audio/source_aligned.m4a` —— 浏览器里听到的就是成片音轨。

### 4.3 `mv/pv/scripts/22_render_1080p.sh`

- 合音轨的输入 `$PV/audio/source_pad.m4a` → `$PV/audio/source_aligned.m4a`（存在性检查也改了）。
- **本次没有跑这个脚本、没有做任何视频渲染。**
