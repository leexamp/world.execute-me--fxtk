## 二、但成片有四个硬伤，全部可量化

我用 `ffmpeg` + 自相关把片子量了一遍。数据在 `measurements.txt`。

### 硬伤 1：剪辑点是"拍脑袋"的 —— **20 刀里 0 刀踩在小节线上**

这歌 **≈129.2 BPM**（onset 自相关 r=0.660），拍长 **0.464s**，小节（4 拍）**1.858s**，起点相位约 **204ms**。

```
现有 20 个剪辑点，落在小节线上（<40ms）的: 0 个
```

**一个都没有。** 于是剪辑在和音乐打架，观众感觉"卡不上、发闷、看不下去"——
**这不是审美问题，是节拍对齐问题。**

单刀偏差实测：

| 剪辑点 | 位置 | 偏离最近的拍 |
|---|---|---|
| #0 | 7.17s | **201ms** |
| #2 | 23.93s | **215ms** |
| #11 | 114.00s | **223ms** |
| #15 | 166.03s | **221ms** |

129 BPM 下半拍只有 232ms。**223ms 的偏差 ≈ 半拍**，等于把重音全踩在反拍上。

### 硬伤 2：剪辑密度差 5.8 倍

```
平均每刀 10.62s = 22.9 拍 = 5.7 小节
```

这歌的常规 MV 密度应该是 **1–4 小节一刀**：

| 密度 | 应有刀数 | 现有 |
|---|---|---|
| 每小节一刀 | 114 | **20** |
| 每 2 小节一刀 | 57 | **20** |
| 每 4 小节一刀 | 29 | **20** |

**连最松的"每 4 小节一刀"都不够。** 长度 14 秒的静止画面在这歌里是不成立的。

### 硬伤 3：31% 的画面偏暗，平均亮度只有 74/255

```
暗帧(<40) 65/212 秒 = 31%    平均亮度 74.0    亮帧(>100) 53 秒
```

终端卡片本身没问题，问题是**卡片只占画面的很小一部分，周围全是空黑**。
`t=78s` 那帧：窗口里 4 行字，占画面高度不到 20%，其余全空。

### 硬伤 4：构图浪费画幅

`t=64s` 那帧：`$ git show --stat ...` 只打了 10 个字符，剩余 90% 是空的。
**打字机动效的速度是按"读代码"设计的，不是按 129 BPM 设计的。**

## 三、重剪要求（按我的标准）

**核心原则：内容一个镜头都不删，只把"什么时候换镜头"改成跟着音乐走。**

### R1. 一刀踩一小节（强制）

- 网格已生成：`incoming/beat_grid.json`（115 个小节线，含 BPM / 相位 / 全部时间点）
- **所有切换必须落在 `bars[]` 的时间点上，误差 <40ms**
- 快切段落（见 R2）允许落在**拍**或**半拍**上

```python
import json
g = json.load(open('incoming/beat_grid.json'))
bar, beat = g['bar_s'], g['beat_s']
# 第 n 小节线 = g['bars'][n]
```

### R2. 按段落能量给密度（目标 ~116 刀）

| 段落 | 时间 | 密度 | 刀数 |
|---|---|---|---|
| intro | 0:00–0:12 | 每小节 | 7 |
| 建立 | 0:12–0:28 | 每小节 | 9 |
| 生长 | 0:28–0:47 | 每 2 小节 | 6 |
| dizzy / 残影 | 0:47–1:03 | **每小节** | 9 |
| 真相 | 1:03–1:28 | 每小节 | 14 |
| 重构 | 1:28–1:48 | 每 2 小节 | 6 |
| 诚实 | 1:48–2:08 | 每 2 小节 | 6 |
| **EXECUTION** | 2:08–2:46 | **每拍/半拍** | **41** |
| 六窗口 | 2:46–3:04 | 每小节 | 10 |
| 尾声 | 3:04–3:32 | 每 2 小节 | 8 |

**合计 ~116 刀（现在 20 刀）。**

> `EXECUTION` 快剪段本来就是我分镜里设计的爆点——现在它是全片最安静的地方之一。
> 那段要**每拍甚至半拍切**，41 刀塞进 38 秒。

### R3. 素材完全够，不需要补拍

`footage/` 现有 **19 个 MP4 / 347MB**：

- 12 个演示页：`page_3d / components / gfx / input / paint / particles / scroll / stress / wave`
- 4 段历史：`ghost_before / ghost_after / rgb565_v21 / slim_146a68d`
- 5 种分辨率 + `ui_hover`
- 共 **4449 帧 PNG** 可做定格/变速

同一段素材可以在不同小节里用不同片段/倍速，**这是 MV 的正常做法**，不是注水。

### R4. 每刀必须有"信息变化"

不要"同一帧停 2 小节"。切了就要有变化，至少满足一条：

- 换素材 / 换片段
- **同一素材的不同时间点**（例如波形页的 0.5s 处和 3.2s 处）
- 加一层 HTML 动效（数字跳动、diff 行逐条落）
- 推拉/位移（`transform: scale()` / `translate()`，要能量化到小节）

### R5. 把"暗"改掉

- 终端卡片的**打字速度按 129 BPM 调**：每个小节至少推进一屏，不要 10 秒打 10 个字符
- 卡片四周的空黑：用**放大的终端底纹**或**微妙的网格/扫描线**填，别留纯黑
- 目标：**平均亮度 ≥ 100，暗帧(<40) 占比 <8%**

### R6. 保留全部诚实性约束（不许为了好看而放松）

- `CONTEXT.md` 第二节"❌ 假的"那张表里的东西，**一条都不许演**
- 你已做的诚实处理（"肉眼分不出来"那段、高 DPI 留白、做不到清单）**全部保留**
- 新增的动效不得引入任何"看起来像在实现但没实现"的画面

## 四、验收标准（可自动检验）

剪完后跑这几条，**全部达标才算过**：

```bash
# 1) 剪辑密度（目标 >= 90 刀）
ffmpeg -v info -i out/world_execute_me_fxtk_720p.mp4 \
  -vf "select='gt(scene,0.3)'" -f null - 2>&1 | grep -c pts_time

# 2) 贴小节率（目标 >= 85%）
#    用 incoming/beat_grid.json 的 bars[] 逐刀比对, 误差阈值 40ms

# 3) 平均亮度（目标 >= 100）
ffmpeg -v error -i out/world_execute_me_fxtk_720p.mp4 \
  -vf "fps=1,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=/tmp/y.txt" -f null -
awk -F= '/YAVG/{s+=$2;n++} END{print s/n}' /tmp/y.txt

# 4) 暗帧占比（目标 < 8%）
awk -F= '/YAVG/{v=$2+0; n++; if(v<40)d++} END{printf "%.0f%%\n", d*100/n}' /tmp/y.txt
```

**当前实测**：20 刀 / 贴小节 0% / 亮度 74.0 / 暗帧 31%
**目标**：≥90 刀 / 贴小节 ≥85% / 亮度 ≥100 / 暗帧 <8%
